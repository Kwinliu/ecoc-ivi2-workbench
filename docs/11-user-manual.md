# eCoC / IVI2 工作台使用说明

本文面向实际操作人员，说明如何使用本地 eCoC Workbench 完成 CoC 文件批量导入、车型设定、CoC 内容校验、IVI2 XML 生成、D-Trust 签章、NAP 上传和提交记录检索。

当前系统是本地原型工作台：D-Trust 签章 API、RDW/KBA/VCA 上传 API 目前使用本地模拟回执；生产环境接入时，需要替换为真实 endpoint、证书、API Key、错误码映射和正式 XMLDSig 签章。

## 1. 系统用途

本工作台用于把制造商侧 CoC 数据整理为 IVI/eCoC 处理流程：

1. 上传 Word、Excel、IVI XML 或 CSV 格式的 CoC/车辆数据。
2. 自动抽取 VIN、WVTA/Approval Number、车型、Variant、Version 等字段。
3. 生成 IVI2 XML 草稿。
4. 对 CoC 内容做一致性校验。
5. 对校验通过的草稿执行签章：系统生成待签 XML 的 hash / 签章载荷，并提交给 D-Trust 签章服务。
6. 将 D-Trust 返回的签章结果合入 IVI/eCoC XML，再把签章后的 XML 包上传到配置的 NAP API。
7. 记录提交历史，便于追溯和检索。

## 2. 启动方式

在项目目录中运行：

```bash
npm start
```

启动后浏览器访问：

```text
http://localhost:4173/
```

如果 4173 端口已经被占用，可以改用其他端口：

```bash
PORT=4174 npm start
```

## 3. 页面结构

首页从上到下包括以下区域：

1. 看板
2. CoC 批量上传
3. 上传列表
4. 校验区
5. 车型设定区
6. 提交历史

### 3.1 看板

看板显示当前数据状态，例如：

- 车辆数量
- 草稿数量
- 校验失败数量
- 已生成 XML 数量
- 已签章数量
- 已上传数量
- API 已受理数量

看板用于快速判断当前批次处理进度。

### 3.2 CoC 批量上传

该区域用于上传原始文件。

支持文件类型：

- Word: `.docx`
- Excel: `.xlsx`
- IVI XML: `.xml`
- CSV: `.csv`

操作方式：

1. 点击“选择文件”。
2. 选择一个或多个文件。
3. 系统会自动上传并处理，不需要再点击单独的“上传并校验”按钮。
4. 处理完成后，上传列表会刷新。

也可以直接把文件拖入上传区域。

上传后系统会尝试：

- 抽取 CoC/车辆字段。
- 识别 VIN。
- 识别 Approval Number / WVTA。
- 识别 Type、Variant、Version。
- 创建 IVI/eCoC 草稿。
- 初步生成可处理的 IVI2 数据结构。

如果文件内容不完整，系统仍可能创建草稿，但会在后续校验中显示错误或警告。

### 3.3 上传列表

上传列表是主要工作区。每一行代表一个车辆/CoC 草稿。

主要列包括：

- VIN
- IVI Reference
- Type
- Variant
- Version
- 状态

每行前面有勾选框。批量按钮只作用于已勾选的草稿。

列表下方按钮：

- 校验
- 生成 XML
- 签章
- 上传 NAP

推荐操作顺序：

1. 勾选要处理的车辆。
2. 点击“校验”。
3. 处理校验区显示的错误。
4. 校验通过后点击“生成 XML”。
5. 点击“签章”。
6. 点击“上传 NAP”。

状态列只显示当前最关键状态，例如：

- 校验 待校验
- 校验 未通过
- 校验 通过
- 签章 已签章
- 上传 已上传

### 3.4 校验区

点击“校验”后，上传列表下方会显示校验区。

校验区显示所有被勾选车辆的 CoC 内容检查结果。

每个车辆显示：

- VIN
- 错误数量
- 警告数量
- 处理状态
- 问题表格

问题表格只显示高密度信息：

- 级别
- 项目
- 问题

当前默认只显示错误和警告，不显示系统信息，不显示建议句。

错误表示必须处理，否则不应继续签章和上传。

警告表示需要业务复核；是否阻断流程取决于后续生产规则和车型 CoC 校验范本。

示例：

| 级别 | 项目 | 问题 |
| --- | --- | --- |
| 错误 | 型式批准机构 | 型式批准机构缺失 |
| 错误 | 生产日期 | 生产日期缺失 |
| 警告 | 燃料/能源类型 | 燃料/能源类型缺失 |

当前通用校验关注 CoC 内容准确性，不再把“目标注册国家”作为上传路径校验条件。上传路径由 Approval Number / WVTA e-code 自动判定。

轮胎信息不再作为默认必检警告。后续如果某个车型的 COC 校验范本明确要求轮胎字段，再由该车型范本规则校验。

### 3.5 车型设定区

车型设定区用于维护“某个车型 + Approval Number”对应的默认 API 和 CoC 校验范本。

录入顺序：

1. 输入车型。
2. 输入 Approval Number。
3. 选择签章 API。
4. 选择上传 API。
5. 上传 COC 校验范本。
6. 点击“加入列表”。
7. 点击“保存设定”。

字段说明：

| 字段 | 说明 |
| --- | --- |
| 车型 | 车辆 Type，例如 `SY14`、`AX2T(M)` |
| Approval Number | WVTA / 型式批准号，例如 `e6*2018/858*00264*01` |
| 签章 API | 选择 D-Trust 签章主体 |
| 上传 API | 选择 RDW/KBA/VCA 上传主体 |
| COC 校验范本 | 上传该车型的基准 CoC 样本或校验模板 |

车型设定表用于后续自动匹配：

- 当上传草稿的 Type 和 Approval Number 与设定表匹配时，系统优先使用该行配置的签章 API 和上传 API。
- 如果没有匹配的车型设定，系统使用默认路由规则。

当前默认路由规则：

- Approval Number e-code 为 `e11` 或 `e24` 时，判定为 GB 路径。
- 其他 e-code 判定为 EU 路径。

页面上不再单独显示 EU/GB 列；该判断在后台自动完成。

### 3.6 提交历史

提交历史记录上传结果。

字段包括：

- 时间
- VIN
- NAP
- 状态
- Message ID
- 回执

右上角检索框支持按以下内容搜索：

- VIN
- NAP
- 状态
- Message ID
- 回执文本

示例：

```text
RDW
accepted
RLCSY141000001946
```

## 4. 推荐日常操作流程

### 4.1 首次配置车型

1. 打开工作台。
2. 滚动到“车型设定区”。
3. 输入车型。
4. 输入 Approval Number。
5. 选择签章 API。
6. 选择上传 API。
7. 上传该车型的 COC 校验范本。
8. 点击“加入列表”。
9. 确认表格中出现该车型设定。
10. 点击“保存设定”。

完成后，该车型后续批次会优先使用对应配置。

### 4.2 上传一批 CoC 文件

1. 滚动到“CoC 批量上传”。
2. 点击“选择文件”。
3. 选择多个 Word、Excel、XML 或 CSV 文件。
4. 等待上传处理完成。
5. 查看“上传列表”是否出现对应车辆。

### 4.3 执行批量校验

1. 在上传列表勾选要处理的车辆。
2. 点击“校验”。
3. 查看“校验区”。
4. 对错误项进行处理。
5. 对警告项进行业务复核。

如果错误项未解决，不建议继续签章和上传。

### 4.4 生成 IVI2 XML

1. 勾选校验通过的车辆。
2. 点击“生成 XML”。
3. 上传列表状态会更新。

当前页面不再显示 XML 预览区。如需查看生成文件，应在后端证据目录或后续文件下载功能中查看。

### 4.5 执行签章

1. 勾选已生成 XML 且校验通过的车辆。
2. 点击“签章”。
3. 系统按车型设定或默认路由选择签章 API。
4. 签章成功后，状态变为“签章 已签章”。

当前 D-Trust 签章为 mock。生产环境应替换为真实 D-Trust API。

生产签章的目标流程是：

1. 系统生成未签章 IVI2 XML。
2. 系统对待签 XML 做规范化处理，并生成 hash / digest / signing payload。
3. 系统把签章请求发送到 D-Trust 服务器。
4. D-Trust 返回签章值、签章 XML 片段或签章回执。
5. 系统保存签章结果，并生成签章后的 IVI/eCoC XML 包。

私钥不应放在本系统前端，也不应明文保存在数据库中。

### 4.6 上传 NAP

1. 勾选已签章车辆。
2. 点击“上传 NAP”。
3. 系统按车型设定或默认路由选择上传 API。
4. 上传成功后，提交历史会新增记录。

当前 RDW/KBA/VCA 上传为 mock。生产环境应替换为真实 NAP API。

生产上传的目标流程是：

1. 系统确认草稿已经校验通过。
2. 系统确认存在 D-Trust 签章后的 XML 包。
3. 系统按车型设定或默认路由选择 RDW/KBA/VCA。
4. 系统把签章后的 IVI/eCoC XML 包上传到对应服务器。
5. 系统保存 NAP 返回的 Message ID、状态和回执。

## 5. API Key 管理

建议生产环境把 API Key 写在环境文件中，不要放到前端，也不要在数据库明文保存。

推荐变量：

```env
DTRUST_EU_REP_1_API_KEY=...
DTRUST_EU_REP_2_API_KEY=...
DTRUST_GB_REP_API_KEY=...

RDW_UPLOAD_API_KEY=...
KBA_UPLOAD_API_KEY=...
VCA_UPLOAD_API_KEY=...
```

生产环境还应预留 endpoint 和证书配置：

```env
DTRUST_EU_REP_1_ENDPOINT=...
DTRUST_EU_REP_2_ENDPOINT=...
DTRUST_GB_REP_ENDPOINT=...

RDW_UPLOAD_ENDPOINT=...
KBA_UPLOAD_ENDPOINT=...
VCA_UPLOAD_ENDPOINT=...

RDW_CLIENT_CERT_PATH=...
RDW_CLIENT_KEY_PATH=...
KBA_CLIENT_CERT_PATH=...
KBA_CLIENT_KEY_PATH=...
VCA_CLIENT_CERT_PATH=...
VCA_CLIENT_KEY_PATH=...
```

建议文件策略：

- `.env`：本机真实密钥，不提交 Git。
- `.env.example`：只放变量名和示例，不放真实密钥。
- 前端只显示脱敏值，例如 `eu_r...2026`。
- 后端调用 D-Trust、RDW、KBA、VCA 时才读取完整密钥。
- 真实 API Key、证书路径、endpoint 不应写死在 `src/server.js` 中。

## 6. 文件与证据

系统会在本地数据目录保存草稿、XML、签章结果、上传回执等证据。

典型数据包括：

- 草稿记录
- 校验报告
- 生成前 XML
- 签章后 XML
- 上传回执
- 审计记录

这些文件用于问题追踪和合规留痕。

## 7. 常见问题

### 7.1 上传后没有出现车辆

可能原因：

- 文件格式不支持。
- 文件内容不是 CoC 或 IVI 数据。
- Excel/Word 中字段无法识别。
- 文件为空或损坏。

处理方式：

1. 确认文件后缀是 `.docx`、`.xlsx`、`.xml` 或 `.csv`。
2. 确认文件包含 VIN、Approval Number、车型等关键字段。
3. 使用官方样本或已知可解析模板测试。

### 7.2 校验失败是否可以签章？

不建议。当前系统会阻止存在错误的草稿签章。

一般处理顺序是：

1. 先修复错误。
2. 再重新校验。
3. 校验通过后生成 XML。
4. 再签章和上传。

### 7.3 为什么没有 EU/GB 选择列？

EU/GB 路径由 Approval Number / WVTA e-code 自动判断。

当前规则：

- `e11`、`e24`：GB 路径。
- 其他：EU 路径。

因此页面不要求人工维护 EU/GB 字段。

### 7.4 目标注册国家为什么不校验？

当前校验目标是 CoC 内容本身是否准确。

上传路径不依赖目标注册国家，而是依赖 Approval Number / WVTA e-code，所以“目标注册国家缺失”不再作为默认校验项。

### 7.5 轮胎信息为什么不再默认警告？

不同车型/范本对字段要求不同。当前通用校验不把轮胎作为默认必检项。

如果某个车型的 COC 校验范本明确要求轮胎字段，应在后续车型范本校验中启用该规则。

### 7.6 提交历史怎么查？

在“提交历史”右上角检索框输入关键词。

可搜索：

- VIN
- NAP
- 状态
- Message ID
- 回执内容

### 7.7 保存车型设定后没有生效怎么办？

检查：

1. 是否点击了“加入列表”。
2. 是否点击了“保存设定”。
3. 上传草稿中的 Type 是否与车型设定一致。
4. 上传草稿中的 Approval Number 是否与车型设定一致。
5. 是否刷新了页面。

## 8. 当前原型限制

当前系统仍是原型，有以下限制：

- D-Trust 签章为 mock。
- RDW/KBA/VCA 上传为 mock。
- XMLDSig 正式签章尚未接入。
- ICM 官方检查模块尚未完整接入。
- 车型 COC 校验范本的字段级规则仍需进一步实现。
- XML 预览区已移除，后续可改为证据文件查看或下载功能。
- API Key 仍需进一步改造成环境变量读取。

## 9. 建议生产化补充

生产环境建议补齐：

1. 真实 D-Trust 签章 API。
2. 真实 RDW/KBA/VCA 上传 API。
3. mTLS / 证书管理。
4. HSM 或安全密钥管理。
5. XMLDSig 正式签名与验签。
6. ICM 官方检查模块。
7. 车型 COC 校验范本规则引擎。
8. 可下载的签章 XML、上传回执、审计报告。
9. 用户权限、操作日志和审批流程。
10. API Key 环境变量化和密钥轮换机制。
